# BSI — work plan and deferred decisions

**Updated:** 2026-11-22. **Scope:** the independent BSI repository only.
This is the **single entry point for unfinished or deferred BSI work**, not a
historical diary. GitHub issues remain the place for discussion and execution
details. When a task is completed, update this page and its linked issue;
do not maintain a second competing checklist elsewhere.

## Audit: should we keep all intermediate UBS research files?

**Decision: no bulk permanent archive of every generated working file.**
Preserve *editorial knowledge*, source provenance, decisions, abstentions and
the reproducible process; discard reproducible temporary dumps after checking
they contain no unique human decisions.

| Stream | Durable evidence already in Git | Regenerated rather than archived | Residual uncertainty |
| --- | --- | --- | --- |
| UBS Greek | 13 named reviewed JSON decision/headword ledgers, pinned baselines, ~82 source-specific Python tools/tests, rights/release reviews | 137,741-word consolidated private candidates, provisional LEXID tiers, token-position audits, context batches and other `/tmp/` results from `bsi-ubs-greek.yml` | Not every generated token-by-token report is retained. Reproducible CI is **not** proof of any unique unrecorded manual notes being preserved. |
| UBS Hebrew | 14 named review/disposition/approval/abstention JSON files, pinned baseline and ~51 source-specific Python tools/tests, v1.0 readiness and v1.1 feasibility/pilot conclusions | 53,981 potential verse-witness semantic candidate report, 72-token detailed pilot witnesses and full candidate index regenerated by `bsi-ubs-hebrew.yml` | The 72-token pilot's **published conclusion and representative exceptions** are in `V11_CONTEXTUAL_PILOT.md`, but the full original-token witness file is generated only on the runner. |
| Entities | All current reviewed source records, source hashes, original source lock, old decision ledger, quarantine and migration manifest | Older source-plus-overlay comparison output and intermediary distribution JSON | Five inherited relationship claims and changed-identity descriptions still require editorial review; do not mistake an inherited description for a reviewed one. |

**Evidence checked:** current tracked files and the two independently
source-pinned workflows, including their explicit regeneration and validation
steps. Historical benchmark/example and decision files were inspected.
The workflows no longer upload these large working dumps from the public
repository. **No complete human-by-human forensic audit of all historic
runner files was possible**, so do not claim perfect preservation of every
uncommitted research note.

**Retention rule going forward:**

1. Keep **source-linked editorial approvals, rejections, abstentions and
   justifications** in versioned BSI data, where they are directly actionable.
2. Keep exact upstream source revisions and checksums, generators and
   representative tests. A green rebuild must still distinguish a *candidate*
   from a *validated contextual sense*.
3. Do **not** commit private/full UBS dictionaries, MACULA witness rows or
   mass provisional sense guesses just to avoid recalculating them.
4. If a future study produces genuinely new manual reasoning that is
   **not reconstructible**, record its source-specific conclusions before
   allowing ephemeral CI output to expire. A small review ledger is preferred
   to an enormous snapshot.
5. Reconsider restricted durable storage only when a specific irreproducible
   research need is demonstrated and rights/storage are explicitly approved.

- [ ] **P1 · Retire active duplicate BSI ownership in Bible-Resources.**
  Only once the new repository is verified, replace the old active BSI

  appropriate; preserve historical commits, licenses, tags and release
  downloads. This must be a separate, reviewable PR in
  [Bible-Resources](https://github.com/icfmp/Bible-Resources).
- [ ] **P2 · Define the BSI → Bible-Resources delivery contract.**
  BSI produces immutable, owner-approved versioned releases with manifest,
  attribution and SHA-256; Bible-Resources **pulls** an approved fixed version
  and verifies its checksum. No Git-branch copying, automatic republishing
  of historical version numbers or silent release replacement.
  [Issue #1](https://github.com/icfmp/Bible-Resources-Semantic-Index/issues/1).
- [ ] **P2 · Clean the inherited research/doc toolchain after establishing
  callers.** Many UBS READMEs mix chronological reports with current methods.
  Keep durable decisions near each UBS source, current generic processes
  under `docs/`, reusable tools under `scripts/`, and delete genuinely
  obsolete one-off code *only after* protected-release reproducibility checks.
  Do not remove a file solely because its name says `private` or `audit`.
- [ ] **P2 · Establish a direct-edit regression contract for evolving
  entities.** Future tests should verify unique stable source IDs,
  referential consistency, valid original-word IDs, quarantines and
  intentional editorial evidence on actual changed records, without relying
  on an ACAI patch list or fixed historical index digest.

## Completion standard

A task is complete only when its code/data is on the intended repository,
tests pass, changes are source-justified, any editorial decision is reviewed,
provenance and rights remain clear, and the issue/roadmap is updated.
**Implemented ≠ tested ≠ editorially approved ≠ published.**
